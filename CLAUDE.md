# Правила проекта для Claude Code

## Автоматическое создание .gitignore при старте проекта

Если в проекте отсутствует `.gitignore` — создай его с минимальным набором для Python/Telegram-бота:

```
# Environment
.env
.env.*
!.env.example

# Python
*.pyc
*.pyo
__pycache__/
*.egg-info/
dist/
build/
.venv/
venv/
.pytest_cache/
*.log

# Google service account (приватные ключи)
credentials*.json
service_account*.json
*-service-account*.json

# Локальные БД
*.sqlite
*.sqlite3
*.db

# Playwright / QA
playwright-report/
test-results/
screenshots/

# OS
.DS_Store
Thumbs.db
```

## Архитектура — ARCHITECTURE.md

При внесении любых изменений в код — фиксируй логику и структуру проекта в `ARCHITECTURE.md`.
Если файла нет — создай его.

---

## Вопросы и ответы — ANSWERS.md

Если что-то непонятно — задавай вопросы пользователю.
Ответы фиксируй в `ANSWERS.md` так, чтобы суть была понятна без самого вопроса (записывай суть, а не диалог).
Если файла нет — создай его.

---

## Безопасность — SECURITY.md и SECURITY-CHECKS.md

Все принятые решения по безопасности фиксируй в `SECURITY.md`.
Если файла нет — создай его.

После каждого изменения кода проводи проверку на утечку данных и записывай результат в `SECURITY-CHECKS.md`.
Если файла нет — создай его.

Запрещено записывать в любые `.md` файлы: логины, пароли, токены, приватные ключи и любые другие чувствительные данные.

### Обязательные правила
- Если в проекте есть `.env` — он **всегда** должен быть в `.gitignore`
- Если есть JSON с `"private_key"` — добавь его явно в `.gitignore`
- `.env.example` всегда разрешён (только плейсхолдеры, без реальных значений)
- Никогда не коммить файлы с секретами (`.env`, `credentials*.json`, `service_account*.json`)

Если файла нет — создай его.

## Тестирование — QA.md и FULL-QA.md

При написании кода сразу планируй тестирование.
Фиксируй пользовательские действия, которые нужно проверить через Playwright.
После внесения изменений проводи тестирование.
Если Playwright не установлен — установи его.

Формат записи в `QA.md`:

```
Тест N1
1 - Тест "[название]" упал.
2 - Ошибка: [описание, вывод из консоли]
3 - Исправил: [описание исправления]
4 - Скриншот: [путь до скриншота]
---------------------------------------------
Тест N2
...
```

Если файла нет — создай его. Пиши кратко, по сути.

Если пользователь пишет "провести тест" — проводи тест и составляй итоговую таблицу в `FULL-QA.md` с результатами всех проведённых тестов.
Если файла нет — создай его.

---

## Задачи для пользователя — TODO.md

Если требуется действие от пользователя, которое ты не можешь выполнить сам — заноси в `TODO.md`.
Заноси только то, что ты не можешь сделать самостоятельно.
Если файла нет — создай его.

При каждом ответе проверяй: есть ли невыполненные задачи в `TODO.md` — напоминай об этом пользователю.
Если пользователь выполнил задачу — отметь её `✓ OK`.
Если можешь проверить выполнение задачи сам — проверь и пометь выполненной.

---

## Что не читать / не включать в контекст

- `.env`, `.env.*` — секреты окружения
- `*.json` кроме `package.json` / `package-lock.json` — могут содержать приватные ключи
- `*.log` — могут содержать PII
- `*.sqlite`, `*.sqlite3`, `*.db` — локальные базы данных
- `__pycache__/`, `*.pyc`, `*.pyo`, `.pytest_cache/`, `.venv/`, `venv/`
- `playwright-report/`, `test-results/`, `screenshots/`
